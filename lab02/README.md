## Множества и мультимножества в SQL

Вариант 1: A — товары, купленные клиентами штата SP,
B — товары, купленные клиентами штата RJ.
Учитываются только заказы со статусом delivered.

## Результаты

| Результат | Количество |
|---|---:|
| A, строки с повторами | 46 448 |
| A, уникальные товары | 18 709 |
| B, строки с повторами | 14 143 |
| B, уникальные товары | 7 672 |
| A ∪ B — UNION | 22 211 |
| UNION ALL, строки с повторами | 60 591 |
| A ∩ B | 4 170 |
| A − B | 14 539 |
| B − A | 3 502 |
| EXISTS без DISTINCT, строки с повторами | 22 731 |
| EXISTS с DISTINCT, уникальные товары | 4 170 |

## Выводы

UNION, INTERSECT и EXCEPT без ALL удаляют дубликаты.
Обычный SELECT и UNION ALL могут сохранять повторы.

Пересечение реализовано также через EXISTS.
Без DISTINCT получено 22 731 строка при 4 170 уникальных товарах.

Объединение и пересечение коммутативны:
сравнение результатов в обоих порядках дало 0 различий.

Разность некоммутативна: A − B и B − A имеют разное
количество элементов — 14 539 и 3 502 соответственно.

## Контрольные вопросы

1. Почему UNION обычно дороже UNION ALL?
   UNION дополнительно удаляет дубликаты, что требует
   вычислений и памяти. UNION ALL сохраняет все строки.

2. Почему нельзя судить о порядке строк без ORDER BY?
   Без ORDER BY порядок выдачи не гарантирован
   и может меняться между выполнениями запроса.

3. Чем множество отличается от мультимножества?
   В множестве элементы не повторяются,
   а в мультимножестве повторы допускаются.
