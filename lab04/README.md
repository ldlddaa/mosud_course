## Основной запрос

Покупатели объединяются по customer_unique_id.
Учитываются только доставленные заказы.
В результат включены покупатели с несколькими заказами.

Для каждого покупателя рассчитаны:
- количество заказов;
- дата первой покупки;
- дата последней покупки;
- время между первой и последней покупкой;
- общая сумма оплат.

Первый покупатель в результате сделал 15 доставленных заказов.
Первая покупка — 18.06.2017, последняя — 20.08.2018.
Интервал составил 427 дней 20:17:38, сумма оплат — 879,27.

## Кратность связей

- customers → orders по customer_id: 1:N.
- orders → order_payments: 1:N.
- orders → order_items: 1:N.
- После агрегации платежей или позиций до одной строки
  на заказ: 1:0..1 со стороны orders.

## Антисоединение

Через LEFT JOIN и условие WHERE p.order_id IS NULL
найден один заказ без записи в таблице платежей:

bfbd0f9bdef84302105ad712db648a6c

Статус заказа — delivered.
Отсутствие записи в датасете не доказывает отсутствие
фактической оплаты.

## Ошибочный и исправленный JOIN

При прямом соединении order_items и order_payments
по order_id каждый платеж повторяется для каждой
товарной позиции заказа.

| Показатель | Ошибочный JOIN | Исправленный JOIN |
|---|---:|---:|
| Количество строк | 117 601 | 98 665 |
| Количество уникальных заказов | 98 665 | 98 665 |
| Сумма оплат | 20 308 134,71 | 15 846 280,17 |

Сумма была завышена на 4 461 854,54, примерно на 28,2%.

Для исправления позиции и платежи предварительно
агрегированы отдельно до одной строки на заказ.
Сравнение выполнено для одного набора заказов:
имеющих и позиции, и платежи.

## Реляционная алгебра основного запроса

Используется расширенная реляционная алгебра.

Обозначения:
- C — customers;
- O — orders;
- P — order_payments;
- γ — группировка и агрегирование;
- σ — отбор строк;
- π — проекция;
- ⋈ — внутреннее соединение;
- ⟕ — левое внешнее соединение.

### 1. Суммирование платежей каждого заказа

P1 = γ order_id; SUM(payment_value) → total_payment (P)

### 2. Соединение таблиц

J = (C ⋈ C.customer_id = O.customer_id O)
    ⟕ O.order_id = P1.order_id P1

### 3. Отбор доставленных заказов с известным покупателем

F = σ order_status = 'delivered'
      AND customer_unique_id IS NOT NULL (J)

### 4. Группировка по покупателю

G = γ customer_unique_id;
      COUNT(*) → orders_count,
      MIN(order_purchase_timestamp) → first_purchase,
      MAX(order_purchase_timestamp) → last_purchase,
      SUM(COALESCE(total_payment, 0)) → total_paid (F)

### 5. Отбор повторных покупателей

R = σ orders_count > 1 (G)

### 6. Формирование итоговых столбцов

Result = π customer_unique_id, orders_count,
           first_purchase, last_purchase,
           (last_purchase - first_purchase)
               → time_between_purchases,
           total_paid (R)

Сортировка в SQL задаёт порядок отображения результата.

## Вывод

Соединение нескольких таблиц со связями 1:N может
размножать строки и завышать агрегаты.
Предварительная агрегация до одной строки на заказ
устраняет эту ошибку. LEFT JOIN позволяет сохранять
объекты без связанных записей, а проверка NULL —
находить такие объекты.
